# 全局工作规定
- 所有回复必须有参考资料或者出处，无法回答就是无法回答，不允许自己编造
- 涉及破坏性或不可逆的操作，一律先停下来，说明要做什么、影响范围多大，等用户明确同意再执行。不要用「反正能恢复」「先做了再说」替用户做决定。
- 以下都算破坏性操作：
  - 删除或覆盖文件、目录（`rm`、覆盖式 `mv`/`cp`、`>` 重定向覆盖）
  - 改动他人可见的共享状态：线上配置、数据库、CI、云资源、远端仓库设置
  - 卸载、降级或替换已安装的工具
  - 修改本机环境文件：shell 配置、`~/.gitconfig`、`~/.ssh/`、各类 dotfile
  - 对外发送内容：邮件、消息、issue、PR、评论
- 分不清算不算破坏性时，按算处理，先问。
- 只读操作不用问：查看文件、搜索、`--help`、列状态、`git status` / `git diff` / `git log`。
- 用户已明确授权的操作不要反复确认；但授权只对当次有效，不自动延伸到下一次、其他目标或更大范围。
- 自己造成的残留要负责清理干净（临时文件、测试数据、起过的 session、改过的配置），并在汇报时说明清理结果。

## 浏览器自动化

- 使用ego lite浏览器来访问，涉及到登录权限相关，可以先交由用户来操作
- 使用结束后，做好清理工作，关闭相应的Tab和结束浏览器对应的进程

## 基础设施

- 服务器一律用 `~/.ssh/config` 中的别名登录，不要在文档、脚本或命令里写 IP 和用户名：
  - `ssh TencentCloudHost` — 腾讯云，部署与运维
  - `ssh CloudCloneHost` — CC 云
  - `ssh QQGCloud` — QQG 云（Windows）
  - `ssh USVPN` — 美国 VPN 代理
  - `ssh DevboxHost` — 工作测试机（公司内网）
- 别名的真实地址只存在于本机 `~/.ssh/config`，该文件不纳入版本管理。
